# The mock for CI and "Try it", local Ollama with repeats for published results

## Context and Problem Statement

Three audiences need different runs. CI needs a fast, deterministic, free run. A
visitor trying the tool needs it to work with no key. The README needs numbers that
describe a real model, regenerated by a script anyone can run without paying.

## Considered Options

- The mock everywhere, README included
- A hosted model with an API key for everything
- The mock for CI and "Try it", local Ollama for the published results, with the run repeated

## Decision Outcome

Chosen option: the mock for CI and "Try it", local Ollama for published results,
because the mock (`llm/mock.py`, an answer derived from the SHA-256 of the prompt)
gives identical numbers on every machine in seconds, while Ollama gives real-model
numbers with no key. `scripts/reproduce.py` runs Ollama by default
(model under test `qwen3.5:0.8b`, judge `qwen3.5:4b`) and `--mock` runs the mock;
both write one section of `results/manifest.json`, and
`tests/unit/test_readme_results.py` fails when the README and the manifest disagree.

Ollama answers are not bit-stable even at temperature 0, so the Ollama mode runs each
pair 3 times and records every repeat plus the median and range (`--repeats`).

### Consequences

- Good: CI and "Try it" need no key and print the same result everywhere
  (`CRITICAL · accuracy -30.19 pp`, `results/manifest.json`, `runs.mock`).
- Good: the manifest records the Ollama version and both model digests
  (`runs.ollama.model`), so a published number can be traced to exact weights.
- Bad: the mock's numbers say nothing about model quality; the README says so.
- Bad: repeats inside one call matched exactly (`runs.ollama.summary`, min equals max),
  yet three calls with the same `lrd` code on 24 October 2026 gave baselines of 41.5%,
  37.7% and 34.0% and one CRITICAL verdict (README, Limits). Repeats in one call do not
  capture variance across calls; a verdict near the boundary needs a rerun.
- Bad: latency is not reported, because a shared local server adds queueing
  (`runs.ollama.model.latency_note`).
